# Что обнаружено в `icon_group_4_58_vai.svg`

Пример имеет `viewBox="0 0 106 45"` и соответствует исходному маленькому IKEA PNG размером 106×45.

## Структура VAI

- 9 залитых `path`.
- 70 команд `L`, 112 команд `C`, 18 команд `Q`.
- Ни одной SVG-команды `A`, ни одного отдельного элемента `ellipse`, `circle` или `rect`.
- Все координаты округлены до 0.01 px.
- Большой синий path описывает прямоугольник и эллиптическое отверстие.
- Жёлтый path описывает эллипс с отверстиями букв.
- Синие буквы повторно рисуются отдельными path поверх жёлтого слоя.
- Есть два почти нулевых служебных path и несколько переходных цветов. Это автоматическая реконструкция, а не вручную очищенный SVG.

Главная причина ровной геометрии — восстановление скрытых слоёв. В растре жёлтый эллипс разделяет видимый синий фон на компоненты, но VAI достраивает полный синий прямоугольник за эллипсом. Аналогично общие уровни букв и симметрия эллипса оптимизируются глобально.

## Численное сравнение с исходным PNG

- VAI: MAE 4.66, RMSE 9.95.
- Старый наш SVG: MAE 41.77, RMSE 89.93.
- Новый geometry-first pipeline без vocabulary: MAE 5.88, RMSE 14.21.

Новый pipeline восстанавливает один скрытый rectangle-layer, один ellipse template, отдельные цветовые глифы и их отверстия. Он использует 7 регионов и 136 адаптивных примитивов вместо квот из CSV.

## Вывод

CSV vocabulary был статистикой команд готового VAI SVG, а не параметрами алгоритма. Принудительное воспроизведение количества L/Q/A/C не связано с локальной геометрией и удалено из веб-конвейера. Правильная последовательность: subpixel reconstruction → palette regions → layer completion → global templates → adaptive curves.
